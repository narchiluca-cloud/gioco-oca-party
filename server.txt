1. VALUTAZIONE DELL'IDEA: ADMIN CON PASSWORD E STANZE
================================================================================

La tua intuizione di separare nettamente l'Admin dai giocatori normali e proteggere
la creazione della stanza con una Master Password è ASSOLUTAMENTE PERFETTA. Ecco
perché a livello di Game Design e di Gestione della Serata fa la differenza:

1. EVITA IL CAOS TRA AMICI (L'EFFETTO "TROPPI CUOCHI"):
   Durante una festa, se chiunque può resettare la partita, avanzare o cambiare
   le regole, dopo due birre qualcuno cliccherà per sbaglio (o per scherzo)
   "Ricomincia partita", rovinando il gioco a tutti. 

2. FLUSSO ELEGANTE E ZERO ATTRITO PER GLI INVITATI:
   - Gli amici NON devono registrarsi o inserire password complesse. Aprono il link
     o inquadrano il QR Code proiettato sul tuo schermo -> Scrivono solo il loro NOME
     -> Sono subito dentro con la loro pedina.
   - Tu invece clicchi sotto "👑 Accedi come Admin", digiti la tua password segreta,
     e prendi il controllo della "Regia della Serata".

3. IL FATTORE "REGIA SEGRETA" (GOD MODE):
   Come Admin hai uno switch segreto sul tuo telefono che ti consente di:
   - Forzare penitenze mirate (es. un gossip piccante creato sul momento per uno specifico amico).
   - Scatenare l'evento "CASCATA / TUTTI BEVONO" a sorpresa.
   - Correggere errori se un telefono perde connessione o spostare una pedina.
   - Dichiarare la vittoria con tanto di coriandoli su tutti i display sincronizzati.

2. ARCHITETTURA DEL SISTEMA (COME GIOCARE TUTTI DAL TELEFONO)
================================================================================

Esistono 2 modalità operative supportate dal nostro codice:

A) MODALITA' HOST IBRIDO / P2P (Zero installazioni - Funziona ORA nel browser):
   Il tuo telefono (Admin) agisce da server logico nella stanza. Gli altri telefoni
   si sincronizzano via WebSockets o stato condiviso locale. Ottimo per test immediati
   e serate improvvisate.

B) MODALITA' SERVER CENTRALE DEDICATO (Raccomandata per serate al 100% stabili):
   Un piccolo server Node.js leggerissimo (consuma meno di 40MB di RAM) riceve le
   connessioni di tutti i telefoni attraverso WebSockets (Socket.io).

3. ANALISI COMPLETA DELLE FALLE (VULNERABILITA', RISCHI E SOLUZIONI)
================================================================================

Come informatico del gruppo, devi conoscere esattamente dove un sistema multiplayer
può cedere durante una festa, sia per colpa di amici smanettoni, sia per problemi di rete.

--------------------------------------------------------------------------------
FALLA 1: CLIENT-SIDE TRUST (DADO TRUCCATO VIA BROWSER DEVTOOLS)
--------------------------------------------------------------------------------
* Il Rischio:
  Se il dado viene calcolato dal browser del giocatore (es. Math.random()), un amico
  che capisce di informatica può aprire la console del telefono o intercettare il
  pacchetto WebSocket e inviare `roll: 6` ogni volta che tocca a lui, evitando
  tutte le caselle con gli shot e vincendo la partita.
* La Contromisura (Server-Authoritative):
  Il client invia SOLO l'intenzione: `socket.emit('player_request_roll')`.
  È il SERVER a generare il numero casuale in modo crittograficamente sicuro
  con `crypto.randomInt(1, 7)` e poi fa il broadcast a tutta la stanza:
  `io.to(roomId).emit('dice_rolled', { value: roll, playerId: current })`.
  Nessun giocatore può barare, nemmeno modificando il codice del proprio telefono.

--------------------------------------------------------------------------------
FALLA 2: BRUTE-FORCE SULLA PASSWORD ADMIN
--------------------------------------------------------------------------------
* Il Rischio:
  Un amico vede il pulsante "Accedi come Admin" e si diverte a provare password a raffica
  ("admin", "1234", "birra", il tuo compleanno) per rubarti il controllo della stanza.
* La Contromisura:
  1. Rate-Limiting sull'endpoint o evento di login admin: dopo 4 tentativi errati da
     uno stesso socket/IP, il server blocca i tentativi per 5 minuti.
  2. Master Password caricata tramite variabile d'ambiente (`ADMIN_PASSWORD`),
     confrontata usando `crypto.timingSafeEqual` per prevenire attacchi di tipo Timing Attack.
  3. Rilascio di un token di sessione casuale (`crypto.randomBytes(32)`).

--------------------------------------------------------------------------------
FALLA 3: DISCONNESSIONI WI-FI E STANDBY DELLO SMARTPHONE (SESSION HIJACKING)
--------------------------------------------------------------------------------
* Il Rischio:
  Durante una serata, i telefoni vanno in standby (schermo bloccato) o il Wi-Fi del pub
  salta per 10 secondi. Se il server si basa solo sul `socket.id` (che cambia a ogni
  riconnessione), l'amico viene rimosso dal gioco, perde la sua casella e deve
  reinserire il nome da capo.
* La Contromisura:
  All'ingresso, il server assegna al client un `sessionToken` persistente che il telefono
  salva nel `sessionStorage` del browser. Se la connessione cade, al rientro il client
  invia: `socket.emit('reconnect_player', { sessionToken, roomId })`.
  Il server riconosce subito il giocatore, ripristina la sua pedina e il suo turno
  senza battere ciglio!

--------------------------------------------------------------------------------
FALLA 4: STORED CROSS-SITE SCRIPTING (XSS) NELLE SFIDE E NEI NOMI
--------------------------------------------------------------------------------
* Il Rischio:
  Se consenti agli amici di inserire il proprio nome o di creare sfide personalizzate,
  qualcuno potrebbe inserire una stringa malevola come:
  `<img src=x onerror="alert(document.cookie)">` oppure uno script che blocca i browser
  degli altri telefoni o fa crashare l'app in loop.
* La Contromisura:
  Sanitizzazione sia lato server che lato client. Nessun testo inserito dagli utenti
  viene mai renderizzato con `innerHTML`. Si usano solo `textContent` oppure una
  funzione di escape rigorosa:
  `str.replace(/[&<>"']/g, (m) => ({ '&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;' }[m]))`.

--------------------------------------------------------------------------------
FALLA 5: RACE CONDITIONS & CLICK FRENATICI (DOPPIO LANCIO)
--------------------------------------------------------------------------------
* Il Rischio:
  Il giocatore preme 5 volte velocemente il pulsante del dado, oppure due giocatori
  provano a lanciare contemporaneamente generando uno stato incoerente sul tabellone.
* La Contromisura:
  Macchina a stati finiti (State Machine) rigorosa sul server:
  - Lo stato della stanza è `WAITING_ROLL`.
  - Solo il giocatore il cui `id === currentTurnPlayerId` ha il permesso di lanciare.
  - Non appena arriva la prima richiesta valida, lo stato passa istantaneamente a
    `MOVING` (tutte le altre chiamate vengono scartate).
  - Al termine dell'animazione e della risoluzione della sfida, lo stato passa a
    `CHALLENGE_ACTIVE`, e solo dopo il click su "Fatto" passa al giocatore successivo.

--------------------------------------------------------------------------------
FALLA 6: ROOM ID SQUATTING E COLLISIONI
--------------------------------------------------------------------------------
* Il Rischio:
  Se i codici stanza sono sequenziali (es. Stanza 1, Stanza 2) chiunque può entrare
  nella stanza di un altro gruppo.
* La Contromisura:
  Codici stanza casuali a 5 caratteri alfanumerici non ambigui (es. `OCA-7X`, `PUB-9K`,
  escludendo lettere confondibili come 0/O e 1/I).

4. GUIDA SETUP STEP-BY-STEP
================================================================================

Hai 3 modi semplicissimi per tirare su il server:

--------------------------------------------------------------------------------
METODO 1: IL TUO PC O UN RASPBERRY PI CON WI-FI DI CASA / PUB (COSTO ZERO)
--------------------------------------------------------------------------------
1. Installa Node.js (scaricalo da https://nodejs.org se non ce l'hai).
2. Nella cartella del progetto apri il terminale PowerShell ed esegui:
     npm install
     npm start
3. Il server si avvierà su porta 3000.
4. Per far connettere gli amici senza toccare il modem di casa:
   Usa CLOUDFLARE TUNNELS (gratuito e istantaneo):
   - Scarica `cloudflared` (https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)
   - Da terminale digita:
     cloudflared tunnel --url http://localhost:3000
   - Cloudflare ti darà un link HTTPS pubblico sicuro tipo:
     `https://oca-serata-pub.trycloudflare.com`
   - Invialo nel gruppo WhatsApp o mostra il QR Code: FUNZIONERA' DA TUTTI I TELEFONI
     ANCHE SE SONO CON RETE DATI 4G/5G!

--------------------------------------------------------------------------------
METODO 2: CLOUD DEPLOY GRATUITO IN 2 MINUTI (RENDER.COM / RAILWAY)
--------------------------------------------------------------------------------
1. Crea un repository privato su GitHub con i file del progetto (`index.html`, `server.js`, `package.json`).
2. Vai su https://render.com o https://railway.app (entrambi hanno tier gratuiti/economici).
3. Clicca "New Web Service" -> Collega il tuo repository GitHub.
4. Come Start Command imposta: `node server.js`.
5. Imposta la variabile d'ambiente:
   `ADMIN_PASSWORD=la_tua_password_segreta_qui`
6. Render ti fornirà un indirizzo HTTPS pubblico permanente (es. `gioco-oca-party.onrender.com`).

--------------------------------------------------------------------------------
METODO 3: DOCKER COMPOSE (PER VERI SYSADMIN)
--------------------------------------------------------------------------------
Se hai una VPS Linux (Hetzner, OVH, DigitalOcean o NAS casalingo), ti basta eseguire:
     docker compose up -d
Tutto viene isolato in un container sicuro con riavvio automatico in caso di crash.

5. SPECIFICA DEGLI EVENTI WEBSOCKET (SOCKET.IO PROTOCOL)
================================================================================

CLIENT -> SERVER:
- `admin_create_room` { roomName, password, customRules }
- `player_join_room`  { roomId, playerName, avatar }
- `reconnect_session` { roomId, sessionToken }
- `request_roll_dice` { roomId }
- `challenge_resolved`{ roomId, result: 'done' | 'chicken' }
- `admin_chaos_event` { roomId, adminToken, targetPlayerId, action, message }

SERVER -> CLIENT:
- `room_state_update` { room, players, activePlayerId, currentTile, phase }
- `dice_rolled_event` { rollValue, playerId, targetTileId }
- `challenge_triggered` { player, tile, customText }
- `victory_declared`  { winnerPlayer }
- `error_notice`      { message }
